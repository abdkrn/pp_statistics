# PP Statistics Bot

Telegram-бот для автоматического подсчёта заявок/проектов, которые руководитель распределяет между менеджерами.

Бот работает в рабочем Telegram-чате менеджеров и фиксирует только те назначения, которые были явно сделаны руководителем.

---

## 1. Назначение бота

Основная задача бота — автоматически вести статистику распределения заявок между менеджерами.

Рабочий сценарий:

```text
Заявка с сайта
      ↓
Руководитель отправляет/пересылает её в рабочий чат
      ↓
Руководитель назначает менеджера
      ↓
Бот распознаёт назначение
      ↓
Назначение сохраняется
      ↓
Статистика менеджера увеличивается на +1
```

Пример:

```text
@ilya, в работу
```

Бот определяет, что заявка назначена Илье, и записывает одно назначение.

---

# 2. Основная логика

## 2.1. Кто считается назначающим

Бот учитывает только сообщения, отправленные пользователями, указанными в `ADMIN_IDS`.

То есть если обычный менеджер напишет:

```text
@ilya, в работу
```

это **не будет засчитано**.

Если такое сообщение отправит руководитель/администратор:

```text
@ilya, в работу
```

бот создаст назначение.

---

## 2.2. Какие сообщения считаются назначением

Бот распознаёт конструкции:

```text
@ilya, в работу
@ilya в работу
@ilya — в работу
@ilya - в работу
```

Регистр не имеет значения:

```text
@ilya, В РАБОТУ
```

также считается назначением.

Допускается пробел после username и перед фразой.

---

## 2.3. Какие сообщения НЕ считаются назначением

Следующие сообщения не увеличивают статистику:

```text
@ilya
@ilya привет
@ilya проверь заявку
@ilya возьми заявку
@ilya посмотри
@ilya обработай клиента
```

Ключевым условием является наличие конструкции:

```text
@username + "в работу"
```

---

# 3. Рабочий чат

Бот обрабатывает назначения только в чате, ID которого указан в:

```env
WORK_CHAT_ID
```

Сообщения из других чатов не учитываются.

---

# 4. Telegram ID менеджера

Основным идентификатором менеджера является его настоящий Telegram ID.

Пример записи:

```json
{
  "telegram_id": 123456789,
  "username": "ilya",
  "name": "Илья",
  "active": true
}
```

`username` используется для отображения и поиска, но основная связь менеджера с данными выполняется через `telegram_id`.

Это важно, потому что Telegram username может измениться.

---

# 5. Права пользователей

В боте есть два типа пользователей.

## Администратор

Telegram ID администратора находится в:

```env
ADMIN_IDS
```

Администратор может:

* смотреть статистику;
* смотреть список менеджеров;
* добавлять менеджеров;
* деактивировать менеджеров;
* переименовывать менеджеров;
* вручную корректировать статистику.

## Обычный пользователь

Обычный пользователь может:

* смотреть статистику;
* использовать `/help`.

# 6. Команды

## `/help`

Показывает доступные команды.

Для обычного пользователя:

```text
/info — статистика
```

Для администратора также отображаются административные команды.

# 7. `/info`

Показывает статистику за текущий месяц.

Пример:

```text
📊 Статистика за сентябрь 2026

Илья — 12
Амир — 10
Миша — 15
Алексей — 8

━━━━━━━━━━━━
Всего — 45
```

В статистике отображаются все активные менеджеры, включая менеджеров с нулевым количеством заявок.

---

# 8. Навигация по статистике

Можно:

* выбрать месяц;
* посмотреть статистику за всё время;
* посмотреть общую статистику по месяцам;
* вернуться назад.

---

Показывает все назначения, сохранённые ботом.

```text

━━━━━━━━━━━━
```

## 8.3. Статистика по месяцам

Позволяет посмотреть общее количество назначений за каждый месяц.

# 9. `/managers`

Команда доступна только администраторам.

Показывает список менеджеров и их статус.

Пример:

```text
👥 Менеджеры

🟢 Илья — @ilya
🟢 Амир — @amir
🔴 Миша — @misha
```

Обозначения:

```text
🟢 — активный менеджер
🔴 — деактивированный менеджер
```

История деактивированного менеджера не удаляется.

---

# 10. Добавление менеджера

## `/add_manager`

Формат:

```text
/add_manager @username Имя
```

Пример:

```text
/add_manager @ilya Илья
```

Менеджер будет добавлен в список.

---

## Важно про Telegram ID

Для корректной работы статистики менеджер должен иметь настоящий Telegram ID.

Не следует использовать выдуманные или вручную придуманные ID.

Если Telegram ID менеджера уже известен, его необходимо сохранить в `managers.json`.

Пример:

```json
{
  "telegram_id": 123456789,
  "username": "ilya",
  "name": "Илья",
  "active": true
}
```

---

# 11. `/remove_manager`

Деактивирует менеджера.

Формат:

```text
/remove_manager @username
```

Пример:

```text
/remove_manager @ilya
```

После выполнения:

```text
✅ Менеджер Илья деактивирован.

Историческая статистика сохранена.
```

Деактивация не удаляет исторические назначения.

Менеджер перестаёт быть активным, но его предыдущая статистика остаётся.

---

# 12. `/rename_manager`

Изменяет отображаемое имя менеджера.

Формат:

```text
/rename_manager @username Новое Имя
```

Пример:

```text
/rename_manager @ilya Илья Петров
```

После этого в статистике будет отображаться:

```text
Илья Петров — 12
```

---

# 13. `/add_stat`

Ручное увеличение статистики.

Используется администратором, если необходимо добавить несколько заявок вручную.

Формат:

```text
/add_stat @username количество
```

Пример:

```text
/add_stat @ilya 5
```

Результат:

```text
Илья +5
```

---

# 14. `/remove_stat`

Ручное уменьшение статистики.

Формат:

```text
/remove_stat @username количество
```

Пример:

```text
/remove_stat @ilya 2
```

Результат:

```text
Илья -2
```

Команда предназначена для исправления статистики, если количество заявок было посчитано неправильно.

---

# 15. Автоматический подсчёт

Основной механизм подсчёта работает автоматически.

Например, руководитель пишет в рабочем чате:

```text
@ilya, в работу
```

Бот:

1. проверяет, что сообщение находится в `WORK_CHAT_ID`;
2. проверяет, что автор сообщения входит в `ADMIN_IDS`;
3. анализирует текст;
4. определяет менеджера;
5. получает Telegram ID менеджера;
6. создаёт запись назначения;
7. увеличивает статистику.

---

# 16. Защита от дубликатов

Каждое автоматическое назначение получает уникальный ID:

```text
chat_id + message_id
```

Поэтому одно и то же сообщение не должно учитываться дважды.

Это особенно важно при:

* повторном запуске бота;
* импорте истории;
* обработке одного сообщения несколькими процессами.

---

# 17. Хранение данных

Бот использует JSON-файлы.

Основные файлы:

```text
data/
├── managers.json
├── assignments.json
└── settings.json
```

---

## `managers.json`

Содержит список менеджеров.

Пример:

```json
[
  {
    "telegram_id": 123456789,
    "username": "ilya",
    "name": "Илья",
    "active": true,
    "created_at": "2026-09-24T10:00:00+03:00",
    "updated_at": "2026-09-24T10:00:00+03:00"
  }
]
```

---

## `assignments.json`

Содержит историю назначений.

Пример:

```json
[
  {
    "id": "-100123456_456",
    "manager_telegram_id": 123456789,
    "manager_username": "ilya",
    "chat_id": -100123456,
    "assignment_message_id": 456,
    "assigned_by": 987654321,
    "assigned_at": "2026-09-24T10:15:00+03:00",
    "source": "auto"
  }
]
```

---

## `settings.json`

Файл предназначен для хранения настроек, которые могут понадобиться боту.

---

# 18. Источники назначений

У записи назначения есть поле:

```text
source
```

Возможные значения:

```text
auto
manual
```

`auto` — назначение обнаружено автоматически в сообщении руководителя.

`manual` — назначение добавлено административной командой.

---

# 19. Резервные копии

Бот автоматически создаёт резервные копии данных.

Папка:

```text
backups/
```

Пример:

```text
backups/
└── 2026-09-24/
    ├── managers.json
    ├── assignments.json
    └── settings.json
```

При запуске создаётся backup.

Также бот периодически проверяет необходимость создания ежедневной резервной копии.

Срок хранения резервных копий определяется:

```env
BACKUP_RETENTION_DAYS
```

По умолчанию:

```text
30 дней
```

---

# 20. Безопасная запись JSON

Файлы JSON записываются через временный файл с последующей заменой основного файла.

Это снижает вероятность повреждения JSON при внезапном завершении процесса во время записи.

Для операций записи используется `asyncio.Lock`, чтобы несколько одновременных обработчиков не записывали один файл одновременно.

# 22. Параметры `.env`

## `BOT_TOKEN`

Токен Telegram-бота, полученный через BotFather.

Пример:

```env
BOT_TOKEN=123456789:ABCDEF...
```

---

## `WORK_CHAT_ID`

ID рабочего Telegram-чата менеджеров.

Пример:


Бот учитывает автоматические назначения только в этом чате.

Telegram ID пользователей, которые являются администраторами бота.


По умолчанию:

```env

```

## `BACKUP_RETENTION_DAYS`

Количество дней хранения резервных копий.

Например:

```env
BACKUP_RETENTION_DAYS=30
```

# 26. Telegram Privacy Mode

Для корректной работы в рабочем чате необходимо проверить настройки Privacy Mode бота через BotFather.

Путь:

```text
@BotFather
→ /mybots
→ выбрать бота
→ Bot Settings
→ Group Privacy
```

Для сценария автоматического отслеживания сообщений в рабочем чате Privacy Mode должен быть настроен так, чтобы бот получал необходимые сообщения.

После изменения настройки рекомендуется удалить бота из рабочего чата и добавить его обратно.

# 27. Права бота в рабочем чате

Бот должен находиться в рабочем Telegram-чате.

Также необходимо проверить, что Telegram действительно передаёт боту сообщения, которые он должен обрабатывать.

Особенно важно проверить:

* сообщения руководителя;
* упоминания менеджеров;
* команды `/info`;
* административные команды.

# 28. Проверка работы

После запуска рекомендуется провести тест.

## Тест 1 — статистика

В рабочем чате:

```text
/info
```

Бот должен показать статистику.

---

## Тест 2 — обычное сообщение

Руководитель пишет:

```text
@ilya привет
```

Статистика не должна измениться.

---

## Тест 3 — неправильное назначение

Руководитель пишет:

```text
@ilya проверь заявку
```

Статистика не должна измениться.

---

## Тест 4 — правильное назначение

Руководитель пишет:

```text
@ilya, в работу
```

Статистика Ильи должна увеличиться на 1.

---

## Тест 5 — другой пользователь

Менеджер самостоятельно пишет:

```text
@ilya, в работу
```

Сообщение не должно учитываться, если Telegram ID отправителя отсутствует в `ADMIN_IDS`.

---

# 31. Что делает импорт

Импортер:

1. читает JSON-экспорт Telegram Desktop;
2. перебирает сообщения;
3. определяет автора сообщения;
4. оставляет сообщения администраторов;
5. анализирует текст;
6. ищет конструкции вида:

```text
@username, в работу
```

7. определяет менеджера;
8. создаёт записи назначений;
9. удаляет дубликаты;
10. выводит итоговую статистику.

---

# 32. Повторный импорт

Импортер рассчитан на повторный запуск.

Для назначения используется ID:

```text
chat_id + message_id
```

Поэтому повторная обработка уже импортированного сообщения не должна создавать вторую запись.

После импорта в консоли выводится:

```text
Найдено назначений: ...
Добавлено новых назначений: ...
Пропущено дубликатов: ...
```

---

# 33. Неизвестные менеджеры при импорте

Если бот не смог сопоставить назначение с существующим менеджером, информация сохраняется:

```text

```

Например:

```json
[
  {
    "username": "unknown_manager",
    "message_id": 12345,
    "date": "2026-09-01T10:00:00"
  }
]
```

Это позволяет отдельно проверить назначения, которые не удалось автоматически сопоставить.

# 38. Типовой рабочий процесс

После первичной настройки работа выглядит так:

### Шаг 1

Руководитель получает заявку.

### Шаг 2

Заявка появляется в рабочем Telegram-чате.

### Шаг 3

Руководитель назначает менеджера:

```text
@ilya, в работу
```

### Шаг 4

Бот автоматически фиксирует назначение.

### Шаг 5

В статистике появляется:

```text
Илья — +1
```

### Шаг 6

Руководитель в любой момент может выполнить:

```text
/info
```

и посмотреть текущую статистику.

# 39. Что бот НЕ делает

Бот не считает:

* любое упоминание менеджера;
* сообщения менеджеров;
* сообщения обычных пользователей;
* сообщения из других чатов;
* фразы без `в работу`;
* самостоятельное решение менеджера взять заявку.

То есть сообщение:

```text
@ilya возьми эту заявку
```

не является автоматическим назначением.

А:

```text
@ilya, в работу
```

является назначением, если его отправил администратор в рабочем чате.

# 40. Важные файлы, которые нельзя удалять

Для сохранения истории особенно важны:

```text
data/managers.json
data/assignments.json
```

`assignments.json` содержит историю назначений.

Удаление этого файла приведёт к потере сохранённой статистики, если нет подходящей резервной копии.

Перед ручным изменением данных рекомендуется сделать копию папки:

```text
data/
```

или использовать резервные копии:

```text
backups/
```

# 41. Быстрый запуск

Если `.env` уже настроен:

```bash
cd parity_bot_rewritten
source .venv/bin/activate
pip install -r requirements.txt
python3 bot.py
```

После появления:

```text
Start polling
Run polling for bot @...
```

бот работает.

Для остановки:

```text
Ctrl + C
```

# 42. Минимальная последовательность настройки

1. Создать бота через BotFather.
2. Получить `BOT_TOKEN`.
3. Добавить бота в рабочий чат.
4. Проверить Group Privacy.
5. Получить `WORK_CHAT_ID`.
6. Получить Telegram ID администраторов.
7. Заполнить `.env`.
8. Установить зависимости.
9. Запустить:

```bash
python3 bot.py
```

10. Добавить менеджеров.
11. Проверить `/info`.
12. Проверить тестовое назначение:

```text
@username, в работу
```

13. При необходимости импортировать старую историю через `import_history.py`.

# 43. Конфиденциальность

Файлы:

```text
.env
data/
backups/
logs/
```

могут содержать служебную и рабочую информацию.

Не рекомендуется публиковать их в GitHub или отправлять третьим лицам.

Особенно нельзя публиковать:

```text
BOT_TOKEN
```

Токен Telegram-бота должен храниться только в `.env`.

Если токен случайно стал публичным, его необходимо перевыпустить через BotFather.
